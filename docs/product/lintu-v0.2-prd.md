## 一、一句话产品定义

> **让一个公司的多个员工，在不同设备上登录灵图，看到的是同一份组织内的项目数据；
> 超管发邀请就能加人、给角色，员工能干什么由角色决定。**

----

## 二、用户故事（决定 PRD 范围的 5 个场景）

### 场景 A · 创始人发员工账号
- 场景：景区运营公司「示例景区A旅游有限公司」用灵图。CEO 在 Mac 上拉所有图，希望招的市场专员小张在自己电脑上也能用同一份资产库。
- 流程：CEO 在 灵图 → 「组织 → 成员」输小张手机号 → 选角色「图库使用者」→ 发邀请。小张在自己电脑上装灵图，用手机号登录，进入即看到示例景区A资产库（限制：只能看图、不能删除）。

### 场景 B · 标注师批量打标
- 场景：组织雇了 3 个外包标注师做 AI 打标审核
- 流程：超管邀请 3 人，给角色「标注师」→ 他们能进入「审核」「打标」流程，但**看不到**「分发中心」「API Keys」「OSS 配置」

### 场景 C · 跨城运营协作
- 场景：杭州团队上传新一批图，上海团队第二天就要拿来用
- 流程：杭州团队同事 A 上传 100 张图 → 自动同步到云端 → 上海团队同事 B 打开灵图，看到这 100 张

### 场景 D · 客户独立组织
- 场景：龙蟾科技作为服务方，给「示例景区B」客户独立的组织空间
- 流程：龙蟾运营人员（平台超管）→ 「平台 → 创建组织 → 示例景区B」 →  指定该组织的初始超管手机号 → 示例景区B的人去灵图登录就在自己组织里，看不到示例景区A数据

### 场景 E · 离职处理
- 场景：标注师离职
- 流程：超管 → 「组织 → 成员 → 张三」→ 「移出组织」一键完成。张三的所有 session 立即失效，下次登录看不到任何项目；操作日志保留可追溯。

## 三、核心概念（数据模型 / 业务术语）

### 实体关系
```
Organization (组织)
   │
   ├── OrganizationMember  ← User
   │       └── role  (owner / admin / editor / viewer / labeler / custom)
   │
   ├── Project (项目)        ← 多个项目归属同一组织
   │       │
   │       ├── ProjectMember ← 「组织成员」中的子集才能进入这个项目
   │       │       └── role  (project_admin / editor / viewer)
   │       │
   │       └── Image / Task / BatchRun / ...
   │
   └── (组织级资源：成员邀请 / 计费 / OSS 凭据 / API Keys)
```

### 三层身份模型

| 层 | 谁 | 能做什么 | 例子 |
|---|---|---|---|
| **Platform**（平台） | 龙蟾科技超管 | 创建组织、跨组织运维、平台计费 | 你（系统 root） |
| **Organization**（组织） | 客户公司 | 邀请成员、分配项目、给角色、看本组织所有数据 | 示例景区A CEO |
| **Project**（项目） | 组织内成员 | 操作项目内数据 | 示例景区A-市场组组员 |

### 角色矩阵（v0.2 第一版只做以下几个，其它后置）

#### 组织角色
| 角色 | 邀请人 | 改组织设置 | 创建项目 | 看所有项目 | 看计费 |
|---|---|---|---|---|---|
| `owner` | ✅ | ✅ | ✅ | ✅ | ✅ |
| `admin` | ✅ | ✅ | ✅ | ✅ | ❌ |
| `member` | ❌ | ❌ | ❌ | ❌（仅 ProjectMember 关联的） | ❌ |

#### 项目角色（具体能力）
| 角色 | 看图 | 上传图 | 删图 | 触发 AI 任务 | 改 prompt 库 | 改 OSS / API Keys |
|---|---|---|---|---|---|---|
| `project_admin` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| `editor` | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ |
| `viewer` | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| `labeler` | ✅ | ❌ | ❌ | ❌（仅审核） | ❌ | ❌ |

> 矩阵右侧「改 OSS / API Keys」属于组织级资源，project_admin 在自己项目的子域里有限管理；全局级仍要 org admin。

## 四、功能清单（按模块）

### 4.1 已有 Phase 1 留下的（继承）
- 手机号 + 短信验证码登录
- 超级管理员（`is_root` → 升级为 platform owner）
- ORM 项目隔离（保留，机制不变）
- 操作日志 + 设备管理 + 邀请基础

### 4.2 v0.2 新增功能

#### 4.2.1 组织模块（新）
- **创建组织** — 平台 owner 在「平台管理」页创建；组织名称 / 联系邮箱 / 计费上限
- **组织设置** — 组织 owner/admin 改 logo / 名称 / 时区 / 默认 OSS 配置
- **成员管理** — 看本组织所有成员，分配组织角色
- **删除组织** — 平台 owner 才能；二次确认 + 软删除 30 天可恢复

#### 4.2.2 项目模块（增强）
- **新建项目** — 组织 owner / admin 才能；指定初始 project_admin
- **项目成员管理** — 把组织内的人加入项目，分配项目角色
- **项目归属组织** — 现有项目迁移时全部归属到 default 组织（迁移脚本）

#### 4.2.3 数据云端化（核心）
- **多设备同步** — 组织内所有数据通过云端统一存储；用户在任何设备登录看到一致
- **图片云端存储** — 原图上传 OSS（按组织独立 bucket prefix），缩略图本地缓存
- **冲突解决** — 现有 `__version` 乐观锁基础上扩展「最后写入胜出 + 冲突告警」

#### 4.2.4 权限装饰器（端点级）
- 后端：每个 `/api/*` 端点挂 `@require_role('editor')` 等注解
- 失败 → 403 + 结构化错误码
- 前端：`useCurrentRole()` hook 决定按钮 disable / hide

#### 4.2.5 平台管理页（新）
- 仅平台 owner 可见
- 列出所有组织 / 用户 / 资源用量 / 异常告警

## 五、数据模型变更（schema 增量）

### 新增表

```python
class Organization(Base):
    id              = Column(String, primary_key=True, default=_uid)
    name            = Column(String, nullable=False)
    slug            = Column(String, unique=True, index=True)  # URL 友好版
    logo_url        = Column(String)
    contact_email   = Column(String)
    plan            = Column(String, default='free')  # free / pro / enterprise
    storage_quota_gb = Column(Integer, default=10)
    storage_used_gb  = Column(Float, default=0)
    status          = Column(String, default='active')  # active / suspended / deleted
    deleted_at      = Column(DateTime)  # 软删除
    created_at      = Column(DateTime, default=datetime.utcnow)


class OrganizationMember(Base):
    id              = Column(String, primary_key=True, default=_uid)
    org_id          = Column(String, ForeignKey('organizations.id'), index=True)
    user_id         = Column(String, ForeignKey('users.id'), index=True)
    role            = Column(String, default='member')  # owner|admin|member
    invited_by      = Column(String, ForeignKey('users.id'))
    created_at      = Column(DateTime, default=datetime.utcnow)
    __table_args__  = (UniqueConstraint('org_id', 'user_id'),)
```

### 现有表改造

- `Project` 加 `org_id String FK` → 项目归属组织
- `ProjectMember.role` 从 `'member'` 扩展为 `project_admin|editor|viewer|labeler`
- `ApiKey` / `OssConfig` 加 `org_id` 归属
- `User` 加 `is_platform_owner Bool`（取代 `is_root`，迁移期保持兼容）

### 迁移策略
1. 新建 `organizations` 表 + 默认组织 `default-org`
2. 现有所有 project 全部归到 default-org
3. 现有所有 user 加 OrganizationMember(default-org, role='member')
4. 现有 `is_root=True` user → 设 `is_platform_owner=True` + OrganizationMember role='owner'

## 六、API 设计（关键端点）

```
# 组织
POST   /api/orgs                     创建组织（仅平台 owner）
GET    /api/orgs                     列出我所属的组织
GET    /api/orgs/{org_id}            组织详情
PATCH  /api/orgs/{org_id}            改组织设置
DELETE /api/orgs/{org_id}            软删除（仅平台 owner）

# 组织成员
GET    /api/orgs/{org_id}/members
POST   /api/orgs/{org_id}/members             邀请新成员
PATCH  /api/orgs/{org_id}/members/{user_id}   改角色
DELETE /api/orgs/{org_id}/members/{user_id}   移出组织

# 项目（整体改 org-scoped）
GET    /api/orgs/{org_id}/projects
POST   /api/orgs/{org_id}/projects
GET    /api/projects/{project_id}              （保留兼容）
PATCH  /api/projects/{project_id}/members/{user_id}/role  改项目角色

# 平台
GET    /api/platform/orgs                     列出所有组织（仅平台 owner）
GET    /api/platform/usage                    平台用量
GET    /api/platform/users                    全平台用户列表
```

### 鉴权流程
```
请求 → UserAuthMiddleware → OrgContextMiddleware（新）
   ↓
   1. 从 path / header / state 推断 active_org_id
   2. 查 OrganizationMember 拿当前用户在该组织的角色
   3. 设 request.state.org_role
   ↓
TenantMiddleware → ORM hook 自动加 WHERE org_id IN (...)
   ↓
@require_role('editor') 装饰器 → 检查 role 命中
   ↓
endpoint 执行
```

## 九、风险与权衡

| 风险 | 缓解 |
|---|---|
