## 1. 产品是什么 · 一句话

**灵图是一个景区图片 AI 生产平台**：把原图扫进来，自动质检 / 去重 / 打标 / 算向量，然后用 AI 大批量生成不同风格 / 季节 / 视角的衍生图，最后通过对外 API 把图片库供 UGC 平台按文本检索调用。

不是图床，不是修图软件 —— 它是"让一张原图变成几十张可分发素材"的流水线。

## 2. 适合的角色

- **景区运营 / 内容**：管理素材库、跑批量生图、审核、按 UGC 需求出图
- **设计 / 摄影**：上传原图、调试生成 prompt、对比不同策略
- **产品 / 数据**：通过对外 API 接入到 H5、小程序、UGC 站点
- **技术 / 运维**：配 AI 服务商、配 OSS 同步、监控调用量、调匹配策略

不需要写代码即可完成日常使用。技术配置（API key、OSS、provider）在「设置」里图形化管理。

## 3. 核心概念速记

| 名词 | 含义 |
|---|---|
| **项目** | 一个景区 / 一个独立素材库。可以同时管理多个项目，每个有独立色块标识 |
| **原图** | 摄影师 / 无人机拍的真实照片，从硬盘扫进来 |
| **生成图** | AI 基于原图 + prompt 生成的衍生（扩图 / 风格化 / 换季 / 局部编辑） |
| **打标** | AI 视觉模型给每张图打 12 个维度的结构化标签（场景 / 季节 / 风格 / 情绪…）+ 50-80 字描述 |
| **向量化** | 给每张图算一个跨模态 embedding，是文图匹配的基础（必须做） |
| **Prompt** | 生成图的"指令"，统一管理在 Prompt 库，可以反复使用 |
| **批次 (Batch)** | 一次提交"种子图 × Prompt 列表"的笛卡尔积生成任务，比如 5 张种子 × 10 个 prompt = 50 张衍生图 |
| **匹配** | 给一段文本，从图库里自动找最相关的 N 张图。对外 API 的核心能力 |
| **API Key** | 给外部 UGC 应用调用用的访问凭证，可绑项目 / scope / 限流 |

## 4. 安装与首次启动

### 4.1 安装

应用以 Electron 桌面应用形式分发。打开 `灵图.app` 即可。

### 4.2 首次启动 5 步上手

1. **创建项目**：左侧栏"项目选择" → ⚙ 管理 → 新建。填名称（例：示例景区A）+ 选图片目录
2. **给项目配色**：管理项目对话框里点色块选颜色，方便切项目时一眼区分
3. **配 AI 服务商**：设置 → AI 服务商。至少配一个 vision 模型用于打标，一个生图模型用于 AI 工坊
4. **配 OSS（可选）**：如果要让图片对外可访问，设置 → OSS 配置 → 填阿里云 keys
5. **跑流水线**：见下面"推荐工作流"

## 5. 推荐工作流（完整一遍）

新项目从原图到对外可用，标准流程是这 8 步，按顺序走一遍：

```
扫描 → 质检 → 方向矫正 → 去重 → 向量化 → 打标 → AI 生图 → 对外发布
 ↓     ↓       ↓         ↓      ↓         ↓     ↓          ↓
流水线   流水线   流水线     流水线    流水线      流水线   AI工坊    分发中心
```

### 5.1 扫描 (Scan)

**入口**：流水线 → 扫描

把图片目录里的所有图扫进数据库。计算 file_hash + phash + 拍摄信息。是其他所有步骤的前置条件。

**何时重跑**：往原图目录新增了图片之后。

### 5.2 质检 (Quality Check)

**入口**：流水线 → 质检

自动评估每张图的清晰度（blur_score）+ 亮度，过滤太糊 / 太暗的。结果写到图片状态：`passed` / `rejected`。

**人工复核**：去资产库 → 回收站，看看自动判定为淘汰的，能恢复的恢复。

### 5.3 方向矫正 (Orient)

**入口**：流水线 → 方向

读 EXIF 自动旋转 + AI 检测明显的歪斜，无损纠正（jpegtran，不重新编码）。修正结果落到 `rotated_file_path`，原文件不动。

### 5.4 去重 (Dedup)

**入口**：流水线 → 去重

用 phash 找近似重复，分组里保留质量最好的，其他标记为 `is_kept=false`（不删盘，回收站里能看到）。

### 5.5 向量化 (Embed)

**入口**：流水线 → 向量化

给每张图算一个 2048 维的跨模态 embedding（基于豆包 doubao-embedding-vision）。**这是文图匹配的基础**，没做这步匹配就不能用。

### 5.6 打标 (Tagging)

**入口**：流水线 → 打标

AI 视觉模型给每张图打 12 维标签 + 写 50-80 字描述。维度包括：

- **客观**：scene 场景 / facility 设施 / season 季节 / weather 天气 / angle 视角 / people 人物 / usage 用途
- **主观**：style 风格 / mood 情绪 / palette 调色 / theme 主题 / composition 构图

**速度**：默认并发 24，3500 张图大约 30-60 分钟。可以在「打标」面板调并发数。

### 5.7 AI 生图 (Workshop)

**入口**：AI 工坊 → 选择策略

四类生图任务（每类对应一种"加工方式"）：

| 策略 | 用途 | 例子 |
|---|---|---|
| **扩图 (outpaint)** | 把竖图扩成横图 / 把窗内扩成全景 | 给小红书出 3:4 / 9:16 等不同比例 |
| **风格化 (style)** | 同一张图换风格 | 写实 → 中国画 / 赛博朋克 / 黑白胶片 |
| **换季 (seasonal)** | 同一场景换季 | 春景 → 秋景 / 冬景 |
| **局部编辑 (inpaint)** | 改图片局部内容 | 抠掉游客 / 加云加雾 / 换天空 |

**两种发起方式**：

1. **单次试做**：选一张种子图，调参数，点"生成"，立刻看效果。适合调 prompt
2. **批量生产**：右上角"批量生产" → 选 N 张种子图 + M 个 prompt → 提交批次。等任务中心跑完。适合产线规模化

**Prompt**：在「设置 → Prompt 库」里管理，每个 prompt 绑定一个 task_type（outpaint / style / …）。批量生产时只能选当前 task_type 对应的 prompt。

### 5.8 对外发布

**入口**：分发中心

- **API Keys**：给 UGC 应用 / 外部系统创建访问凭证
- **接口文档**：所有对外 API 的列表 + curl 例子（外部对接方主要看这里）
- **调用日志**：实时看每个 key 的请求记录
- **OSS 同步**：把本地图片推到阿里云 OSS，UGC 拿到的就是 CDN URL

## 6. 模块详解（按侧栏顺序）

### 6.1 仪表盘 (Dashboard)

进入应用的第一屏。看：

- 每项目的图片总数 / 已通过 / 已打标 / 衍生图数量
- 当前正在跑的任务
- 标签分布 top 20

适合用作"今天有什么进度"的快速一览。

### 6.2 流水线 (Pipeline)

按上面 5.1-5.6 顺序执行的 6 个 tab。每个 tab 都长得一样：上面是参数 + 「开始」按钮，下面是当前任务进度卡。

**按钮置灰**：意味着前置步骤没做（例如打标需要先质检通过）。

**任务可暂停 / 取消**：跑一半发现配置错了，直接取消，改参数重提交。

### 6.3 AI 工坊 (Workshop)

左边一排"策略" tab（扩图 / 风格化 / …，加你自定义的）。点中后右侧出参数表 + 单次生成按钮。

右上角："批量生产"按钮 → 弹窗选种子图 + prompts + 并发 + 预算上限 + provider 优先级。

**绕路：从资产库批量送种子**

资产库 → 全选某些图 → 工具栏"进入 AI 工坊" → 自动带种子打开批量对话框。比手动选种子快得多。

### 6.4 任务中心 (Task Center)

5 个 tab：

- **批次**（默认）：所有 BatchRun 列表，每张卡显示进度 + 成功 / 失败 / 跳过 + 已用预算
- **进行中** / **排队中** / **已完成** / **失败**：单个任务粒度

**点开批次详情**：

- 按 prompt 分组的成功率（哪些 prompt 出图差，去 prompt 库下线）
- 失败清单 + 一键全部重试 + 导出 CSV
- 复制此批次配置（基于这个批次的种子 + prompts + 参数开新批次）

**任务卡可识别**：每张卡显示"AI打标 · Prompt: 秋季漂流 · 42 张"这种标签，多个并发任务一眼能区分。

### 6.5 资产库 (Asset Library)

5 个 tab：

| Tab | 内容 |
|---|---|
| **全部图片** | 默认视图。左侧文件夹树，中间网格，右侧 Inspector |
| **相似组** | 自动找出来的近似重复，可以人工合并 / 保留 |
| **衍生关系** | （V3.0 预留） |
| **收藏夹** | （开发中） |
| **回收站** | 被淘汰 / 被去重判定为副本的图，没真删，能恢复 |

**全部图片**核心交互：

- **筛选条**：状态 / 来源 / 标签 / Prompt / 衍生自 …。条件改了立即刷新
- **批量选择**：勾选若干图后，顶部出现操作条："进入 AI 工坊 / 重新处理 / 下载 / 标记通过 / 标记淘汰 / 删除"
- **全选 N 张**：点工具栏"选中全部 X 张（含未加载）" → 跨所有页 / 含未滚动到的部分
- **预览**：双击图片打开 Lightbox。Lightbox 里支持：← / → 切换 / 滚轮缩放 / 双击放大复位 / Esc 或 Space 关闭 / 「找相似」按钮跳到向量近邻
- **键盘 Space**：在网格视图按空格，对当前选中的图开预览；预览里再按空格关闭
- **Inspector（右侧）**：点单张图后右侧展示完整元数据 + 下载 / 打开原文件 / 删除 / 作为种子开新批次 / 看衍生图

**关键提示**：左侧的「文件夹筛选」按 `relative_dir` 分组，原图按拍摄日期 / 主题分目录组织时特别好用。

### 6.6 覆盖矩阵 (Coverage Matrix)

二维分布图：横轴一个标签维度（如季节）× 纵轴另一个（如场景）。每格是图片数量，颜色编码热度。

**用途**：找出"哪些组合缺图"。例如发现"冬季 × 玻璃滑道"格子是 0，下一轮 AI 生图时优先排这个组合。

点格子可以一键带筛选条件跳到资产库 / 工坊。

### 6.7 匹配实验室 (Match Lab)

3 个 tab：

| Tab | 用途 |
|---|---|
| **试匹配** | 输入文本，立刻看匹配结果 + 各项评分 + 自动权重决策 |
| **匹配分析** | 调用量 / 命中率 / p95 延迟 / 未命中 query top |
| **同义词** | alias → canonical 映射，归一化用户口语词 |

**试匹配核心交互**：

- 输入文本 → 选策略（严格 / 平衡 / 多样）→ 选候选来源（全部 / 仅 AI 生成图 / 仅原图）→ 点开始匹配
- 系统**自动**根据当前项目 + 文本内容决定从哪些项目召回多少张（不需要手动调）
- 「匹配范围决策」面板会显示：每个项目的相关性信号（top-5 余弦均值）+ 是否过阈值 + 最终配额
- 结果卡每张带「项目色块 + 名称」+「相关」标识（如果是跨项目命中）

**调试模式**：勾选「强制单项目」可关闭跨项目召回，仅当前项目内匹配。生产 API 不开放此选项。

**「同义词」**：把用户常说的"傍晚"映射到标签里的"黄昏"，让关键词召回更准。每条 alias → canonical 加完即时生效。

### 6.8 分发中心 (Distribution Center)

4 个 tab：

| Tab | 内容 |
|---|---|
| **API Keys** | 创建 / 轮换 / 停用对外凭证；每个 key 显示今日 / 7 天调用量 + 错误数 |
| **接口文档** | 所有对外 API 的列表 + curl 例子，给外部接入方看 |
| **调用日志** | 选某个 key 看实时请求记录，可按状态码筛选 |
| **OSS 同步** | 把本地图片推到阿里云 OSS，看进度 + 失败原因 |

**创建 API Key 时注意**：

- 每个 key 应该绑定到具体项目（V0.2 即将支持）
- scope 控制权限（推荐 UGC 用 `images:read,images:match`，不给写权限）
- 设 per_minute / per_day 限流，防止单个 UGC 占用所有配额

**OSS 同步**：

- 一次性"全部同步"会推所有未同步的图，几分钟到几十分钟，看图片量
- 增量同步：每张新图（原图 + 生成图）会自动入队后台慢慢推
- CDN URL 会自动写回数据库的 `cdn_path` 字段，UGC 调匹配 API 直接拿到 CDN 直链

## 7. 设置

### 7.1 通用 (General)

- 主题（浅色 / 深色 / 跟随系统）
- 数据目录位置
- 默认项目

### 7.2 AI 服务商 (AI Provider)

最重要的设置。三类配置：

| 角色 | 用途 | 推荐 |
|---|---|---|
| **通用模型（视觉 / 打标）** | 看图打标 + 写描述 | 豆包 Doubao-Seed-2.0-pro 或类似 vision 模型 |
| **图像 Embedding** | 算跨模态向量 | 豆包 doubao-embedding-vision-251215（必须） |
| **图像生成** | AI 工坊出图 | 豆包 Seedream / Gemini / GPT-Image …（按 task_type 选） |

支持自定义中转（custom relay）。每个 relay 配 base_url + api_key + model name。系统按角色分配，一个 relay 可以同时承担多个角色。

**性能提示**：单条接入的中转支持 24-48 并发；OpenAI / Gemini 官方 API 限流严，推荐 ≤ 8。

### 7.3 Prompt 库

所有 AI 生图的"指令"集中管理。每个 prompt 字段：

- `name` 名称（中文，例："秋季漂流封面"）
- `task_type` 绑定的策略类型（outpaint / style / seasonal / inpaint）
- `content` Prompt 文本（可以包含 `{var}` 占位符）
- `tags` 自定义标签（用于在批量对话框里筛选）
- `is_active` 是否启用

**版本化**：编辑 prompt 会自动建版本，旧版本不会丢。

**统计**：列表里显示每个 prompt 的"总产出 / 成功率 / 失败率 / 平均成本 / 最近使用"，效果差的 prompt 一眼可见，下线即可。

**导入文档**：批量从 markdown / docx / xlsx 导入一组 prompt（V0.2 实现，待开放）。

### 7.4 标签体系 (Tag Schema)

12 个维度，每个维度可以自定义可选值。修改后影响：

- AI 打标的输出范围
- 资产库筛选条
- 覆盖矩阵的轴选项

每个标签值显示「命中数」徽章（同一张图在该值下被打过多少次），方便发现"死值"（从来没被打过的）和"过热值"（占比超 50% 应该细分的）。

**强烈不要**频繁删除值 —— 已经打过该值的图会变成"孤儿标签"。改 schema 之前先去资产库筛该值看占用情况。

### 7.5 OSS 配置

阿里云 OSS 凭证 + bucket + 自定义域名（可选 CDN 加速）。

- AccessKey 仅本机加密保存，不上传
- 不配置也能跑，但图片只能本机访问，UGC 拿不到

### 7.6 关于 / 数据导出

版本号、build 信息、问题反馈入口。

## 9. 常见问题

### Q1. 打标 / 生图 / 匹配特别慢

按顺序排查：

1. 设置 → AI 服务商，确认 provider 是中转还是官方。中转可以并发 24-48；官方 ≤ 8
2. 任务中心，看是否所有 slot 都被卡住的老任务占着 → 取消 / 暂停旧任务
3. 设置 → 通用，看「最大并发」配置
4. 终端代理是否影响：环境变量 `HTTP_PROXY` / `HTTPS_PROXY` 会拖慢直连 API（系统已自动忽略，但偶尔会泄漏）

### Q2. 试匹配总是搜到别的项目的图

`v0.2` 后已修复。匹配实验室 → 试匹配 会显示"匹配范围决策"面板。如果还是错位：

- 「主项目」是否当前项目？没有就是项目没选对
- 「强制单项目」勾选后还跨项目 → 报 bug

### Q3. OSS 同步失败 / 卡住

分发中心 → OSS 同步，看失败任务的错误信息。常见：

- AccessKey 错 → 设置 → OSS 配置，填新的
- bucket 不存在 / 权限不够 → 阿里云控制台修
- 网络中断 → 系统会自动重试，可以忽略，等恢复

### Q4. 想清理一些被淘汰的图，回收站永久删除卡住

`v0.2` 已修：3000+ 张图删除从超时变成 380ms。如果还是卡，刷新应用再试。

### Q5. 删了项目，磁盘上的图还在吗？

在。删除项目只清数据库记录，磁盘上的图不动。要彻底清，自己去图片目录手动删。这是设计选择 —— 数据安全第一。

### Q6. 同样的 prompt，不同项目跑，效果不一样？

正常。AI 服务商配置的 model 不同，结果就不同。模型本身有随机性，同一 prompt 跑两次也可能出不同图。

### Q7. 给 UGC 应用对接，要走什么流程？

参见 `docs/部署架构与对外接口.md`，单独一份给外部协作者的文档。

## 10. 给运营的几条建议

### 10.1 项目命名

景区名 + 主题（例："示例景区A·夏季漂流" / "山地公园·秋季航拍"）。多个景区时，色块也按景区色系区分（漂流系蓝 / 山地系绿）。

### 10.2 原图目录组织

用日期 + 主题分目录，例：

```
原图/
  2024.11.23 路极飞车开拍/
  2025.05.01 春季航拍/
  2025.07.06 网红打卡日/
```

资产库左侧的"文件夹筛选"会按这个结构分组，找图非常快。**不要把所有图扁平塞一个目录**。

### 10.3 流水线一次跑一遍

项目刚建好时，按 5.1-5.6 顺序整体跑一遍。中间步骤的状态都在数据库里，重启应用不丢。

### 10.4 Prompt 库分层维护

- **常用 / 主力 prompt**：少量（10-30 个），手工调到产出稳定 ≥ 80%
- **实验性 prompt**：随时加，跑小批次（3-5 张）验证，效果好再升级到主力
- **失败率 > 40%** 的 prompt：去 prompt 库标 `is_active=false` 下线，不要让它继续耗 quota

### 10.5 匹配上线前必做的事

1. 评估集 30 条 query 至少标注一半（在试匹配里 ⭐ 标理想答案）
2. 跑一遍匹配分析看「未命中 top」，文本给的需求在库里没图的，去 AI 工坊补
3. 把同义词词典补充到位（最少把"傍晚→黄昏 / 孩子→儿童 / 鸟瞰→航拍"加上）

### 10.6 给 UGC 出第一把 API Key

- 名称：`<UGC 应用名> 生产 v1`
- scope：仅 `images:read, images:match, tags:read`
- 限流：先按预估的 1.5 倍设，例如预估 1000 次/天就设 per_day=1500，per_minute=30
- 创建后立刻把 secret 发给 UGC 后端的负责人，提醒"只显示一次，存到密钥管理工具里"

### 10.7 反馈的闭环

UGC 接入后，匹配分析里会逐渐有数据：

- 命中率（按 query 去重）
- 未命中 query top（被搜过 ≥2 次但没被选中过的 query）

每周看一次未命中 top 列表，**针对性补图 / 调标 / 加同义词**。这是把"匹配能力"从能跑变成好用的关键。
