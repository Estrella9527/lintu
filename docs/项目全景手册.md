## 1. 一句话定位

**灵图**是景区图片 AI 生产 + 对外分发平台。
- **生产端**：Electron 桌面应用，把景区原图经 AI pipeline 处理（打标 / embed / 风格化 / OSS 上传）后形成可检索的素材库。
- **消费端**：UGC 平台调云端 OpenAPI，传入文案 → 拿回 N 张匹配的图（CDN 直链），无须知道任何内部细节。

## 4. 桌面端模块详解（按侧栏顺序）

### 4.1 仪表盘 (Dashboard)
- **目的**：项目库存全景
- **核心卡片**：
  - 总览：图片总数 / 已 OSS 同步 / 已打标 / 已 embed
  - 项目分布：每个景区的 image 数量、tag 覆盖率、generated/original 占比
  - 最近活动：最近 24h 任务执行情况、最近匹配次数
  - 健康提醒：未打标 / 未 embed / 未上传 OSS 的数量

### 4.2 流水线 (Pipeline)
- **目的**：把原始素材文件夹处理成可检索的素材库
- **8 个 stage**（每个 stage 一个 task type）：

  | 顺序 | 名称 | 任务 type | 功能 |
  |---|---|---|---|
  | 1 | 扫描 | `scan` | 遍历项目源目录，建 image 表行；记录 file_hash + relative_dir + EXIF |
  | 2 | 质检 | `quality` | 计算 blur_score / 亮度，超阈值标 reject |
  | 3 | 方向矫正 | `orient` | EXIF 自动旋转 + AI 检测倒置（rotated_file_path） |
  | 4 | 去重 | `dedup` | phash + CLIP 双信号，UnionFind 聚合 dedup_group_id |
  | 5 | 打标 | `tag` | 调 Doubao vision 出 12 维度标签（scene/facility/season/weather/angle/people/usage/style/mood/palette/theme/composition） |
  | 6 | 向量化 | `embed` | 调 Doubao embedding 出 2048d 向量，存 base64 float16 |
  | 7 | OSS 上传 | `oss_upload` | 原图 + 300/800 缩略图传阿里云 OSS，写 cdn_path |
  | 8 | （AI 工坊单独触发） | style/outpaint/seasonal/inpaint | 风格化生成派生图 |

- **任务并发**：默认 `LINTU_API_CONCURRENCY=8`（同时跑几个任务），每个 embed 任务内部 `API_CONCURRENCY=16`（并行 API 调用）

### 4.3 AI 工坊 (AI Workshop)
- **目的**：从原图生成风格化派生图
- **6 个策略**：
  - `style` — UE5 超写实 / Portra 暖片 / 樱花盛放 等风格
  - `outpaint` — 扩图（如把竖图扩成横图）
  - `seasonal` — 季节变换（夏季 → 秋季）
  - `inpaint` — 局部修补
  - `crop` — 裁切
  - `upscale` — 超分
  - `marketing` / `custom` — 营销文案 / 自定义 prompt
- **批次模式**：选种子图 + 选 prompts → 笛卡尔积生产 N 张图 → 走 `batches` 表跟踪
- **派生图自动**：parent_id 指向源图，文件名格式 `{seed-stem}__{prompt-slug}__{id8}.{ext}`

### 4.4 任务中心 (Task Center)
- **目的**：跟踪所有异步任务
- **Tab**：
  - **批次** — BatchRun + subtasks 进度，每 prompt 成功率，预算消耗，暂停/恢复/失败重试
  - **任务** — 单任务列表（type / status / total / processed / 失败原因）
- **失败重试**：subtask 级别，transient/permanent 错误区分

### 4.5 资产库 (Asset Library)
- **目的**：浏览 / 筛选 / 编辑图片元数据
- **Tab**：全部 / 重复 / 已淘汰 / 收藏 / 派生关系
- **筛选**：项目 / scene / season / source_type / quality_status / 文件夹前缀 / 多 tag 组合
- **批量操作**：标星 / 标淘汰 / 删除 / 重新打标 / 重新 embed
- **详情页**：原图 / 缩略图预览，所有 tag 维度，OSS CDN URL，generation_metadata（如果是 generated），变体链（同 parent_id 的兄弟）

### 4.6 覆盖矩阵 (Coverage Matrix)
- **目的**：可视化"标签维度 × 标签维度"的覆盖密度
- **用途**：找出薄弱组合（如"漂流 × 冬季"无图 → 提示运营补素材或 AI 生成）
- **矩阵单元**：行 dim × 列 dim，单元格显示该组合的图数 + 跳转到资产库筛选

### 4.7 匹配实验室 (Match Lab)
- **目的**：调试 / 对比 / 维护匹配策略
- **3 个子 Tab**：
  - **试匹配** — 直接调本地 `/api/match`，可调权重 / 多样性 / 随机度，看候选数 / debug 字段 / 8 张结果图
  - **匹配分析** — 历史匹配记录、调用日志、命中率统计、Top failing queries
  - **同义词** — `~/lintu-data/synonyms.json` 编辑：定义 `孩子→儿童/小朋友/宝宝` 这样的别名表

### 4.8 分发中心 (Distribution Center)
- **目的**：管理对外 API 服务
- **4 个 Tab**：
  - **API Keys** — 创建（Bearer 仅显示一次）/ 停用 / 改 scope / 改限流 / 改 origin allowlist / 改 IP allowlist
  - **接口文档** — 嵌入 Swagger UI / 跳转云端 /docs
  - **调用日志** — `api_request_logs` 表浏览，按 key 筛选，看响应时间、状态码、错误率
  - **OSS 同步** — `oss_sync_jobs` 队列状态，失败行重试，强制重传

## 5. 设置中心七大 Tab

### 5.1 通用 (General)
- 数据目录路径展示（只读）
- 主题切换：浅色 / 深色 / 跟随系统
- 上传策略：单图字节上限 + 超阈值时（直接失败 / 自动缩小）

### 5.2 AI 服务商 (AI Provider)
- **5 大角色分配**：图像 embedding / 图像理解 / 图像生成 / 通用 LLM / 文档解析
- **内置厂商**：Gemini / OpenAI / Qwen / 通义万相 / 即梦 / 智谱 / ComfyUI
- **自定义 Relay**：自由添加 OpenAI 兼容 endpoint（name / base_url / api_key / model / capabilities）
- **测试连接**：每个 provider 卡片可一键 test
- **导出/导入**：右上角 ⬇导出 ⬆导入按钮
  - 导出默认 mask api_key（`sk-X****`），可在弹窗选择是否包含明文
  - 导入识别 mask 值会保留目标机器现有真实 key

### 5.3 提示词库 (Prompt Library)
- **CRUD**：name / category / content / task_type / variables / tags / negative_prompt / version
- **版本管理**：每个 prompt 可派生新版本（parent_id 链），保留历史
- **统计**：每个 prompt 的成功率 / 失败率 / 平均成本
- **文档导入**：上传 md/docx/xlsx/txt/pdf → LLM 解析成结构化 prompt 列表 → checkbox 选择 → 批量入库
- **导出/导入**：JSON 格式跨机器迁移
  - 模式：`skip_existing` / `upsert` / `create_new`

### 5.4 标签体系 (Tag Schema)
- **12 个维度**：scene / facility / season / weather / angle / people / usage / style / mood / palette / theme / composition
- **每个维度**：label / required / multi / values 数组
- **取值热度**：每个 value 旁显示已打标的图数（找出 dead values）
- **导出/导入**：JSON
  - 模式：`merge`（保留旧值，加新值）/ `replace`（完全覆盖）

### 5.5 匹配策略 (Match Strategy) ✨ 新
- **6 个调优控件**，全是服务端默认值（UGC 不需要传，调好即生效）：
  - **策略**：balanced / precise / diverse（信号权重预设）
  - **多样性**：balanced / strict / none（去重粒度）
  - **随机度** (0-1)：滑块。0=确定性，0.4=刷新有变化（推荐生产），1=分数带内大幅打乱
  - **同源去重** (toggle)：开启时同一原图 + 它的所有 AI 变体最多出 1 张
  - **排除带人物** (toggle)：开启时自动 exclude `少量游客/人群/儿童/工作人员` 标签
  - **近期排除窗口** (0-100, 上限 500)：服务端为每个景区维护滑动队列，最近返回过的 N 张图自动排除；附带「清空缓冲」按钮
- **保存动作**：`PUT /api/config` → 写本地 config.json → cloud_sync_worker enqueue → ~1s 内推到云端 PG settings 表

### 5.6 OSS 连接 (OSS Config)
- **目的**：阿里云 OSS bucket 配置（图片实际存储位置）
- **字段**：oss_provider / oss_endpoint / oss_bucket / oss_access_key / oss_access_secret / oss_cdn_base / oss_signed_url_ttl_sec
- **当前状态**：开发中（runtime 已通，UI 待补）

## 7. 匹配 Pipeline 完整链路

每次 `POST /open-api/v1/images/match` 走的链路（commit 锚点见对应章节）：

### Stage 1 · 关键词抽取
- jieba 切词 + 现有标签 schema 匹配 → 得到 `kw.keywords` + `kw.tag_hits`
- 同步、极快（<5ms）

### Stage 2 · Query Expansion (LLM)
- 调通用 LLM provider，把短文案扩展成 15-25 个相关词
- **超时 1.5s** → fallback 到 jieba 兜底
- **缓存**：sha256(model+text) → 1 小时 TTL，**失败也缓存**避免反复浪费 1.5s

### Stage 3 · 文本 Embedding
- 调 image embedding provider（Doubao Ark vision，2048d）
- 把 query text 嵌入到与图片 embedding 相同的向量空间（跨模态）
- **缓存**：sha256(model+text) → 30min TTL，命中 0ms

### Stage 4 · 召回（双路并行）
- **embedding 召回**：per-project numpy matmul（**全库参与**，取 top **400** 张）
- **keyword 召回**：PG ILIKE 全表扫 text_search_blob，按命中数取 top 400
- 两路并行（asyncio.gather），互不阻塞

### Stage 5 · RRF 融合
- Reciprocal Rank Fusion: `1/(60 + rank)` 求和
- 比"分数加权"更稳健（不依赖两路 score 同尺度）

### Stage 6 · 富化 + 过滤
- 一次 SQL 拉所有 image 元数据 + tags
- **Parent-tag 继承**：generated 图自身无 tag 时，用 parent_id 对应原图的 tag（commit f981d56）
- 应用过滤：
  - `source_type` (original / generated)
  - `scene/facility/season/weather/angle/people/usage` 白名单
  - `exclude_tags` 黑名单（含 `no_people` 默认 expand 出来的 4 个 people 值）
  - `folder_prefix`
  - **`cdn_required`**：未上传 OSS 的图直接 skip（commit 3f95103）

### Stage 7 · 打分（5 个加权信号）
- 当前 balanced 默认权重：
  - embedding: 0.45
  - tag: 0.35
  - quality: 0.05
  - diversity: 0.13
  - business: 0.02
- precise / diverse 是另两个预设
- 可通过 `weights` body 字段一次性覆盖

### Stage 8 · 随机度抖动
- 若 `randomness > 0`，每行 score 加 `U(0, randomness × max_score × 0.5)`
- 保留高分优势的同时让中分图有机会上位
- 默认 0.4

### Stage 9 · 分项目配额
- 主项目独占 limit（commit e7b525c：`_PRIMARY_FLOOR_RATIO=1.0`）
- 副项目仍参与 raw_signal 计算（debug 可见），但不分配 quota

### Stage 10 · 多样性去重
- 三轴并行 cap（commit f981d56 + 0e5687f + 469435d）：
  - **parent_id**: `unique_per_source=True` 时 cap=1（同源所有变体最多 1 张）
  - **relative_dir**: cap=2（同文件夹最多 2 张）
  - **(scene, facility) tag combo**: `unique_per_source=True` 时 cap=1
- Padding 阶段强制 parent_cap + tag_cap，杜绝 padding 漏出近重复

### Stage 11 · 服务端 Cooldown
- 每个项目滑动队列（commit b6a3179），默认 N=20
- 最近返回过的 image_id 自动 exclude，UGC 完全无感
- 内存态，sidecar 重启清零

### Stage 12 · 客户端 exclude_ids
- UGC 在 `body.exclude_ids` 传入"已展示过的"id 列表
- 与 cooldown 队列 union 后传给 enrich 阶段

### Stage 13 · URL 拼装
- 每张图返回：
  - `url` — OSS CDN 直链（`is_read_configured()` 通过则 CDN，否则 fallback `/file` 端点）
  - `thumbnail_url` — `_300.jpg` 缩略图
  - `fallback_url` — 等于 `url`，UGC 用 `<img onerror>` 兜底（commit 0b2c9ae）

详细策略文档：[`MATCH-STRATEGY-DETAILS.md`](MATCH-STRATEGY-DETAILS.md)

## 8. 同步与缓存机制

### 8.1 本地 → 云端同步（cloud_sync_worker）

```
本地写操作 (image / project / api_key / synonyms / tag_schema / config)
    │
    ▼
enqueue 到 cloud_sync_jobs 表 (durable, SQLite)
    │
    ▼
worker tick (30s 间隔，或 wakeup() 立即触发)
    │
    ▼
按 entity_type 分批 (batch_size=50)
    │
    ▼
POST cloud /internal/sync/{type}
    │
    ▼
cloud PostgreSQL 接收，更新对应表
```

**关键特性**：
- **Durable**：sidecar 重启不丢事件，pending 行下次接着推
- **去重**：同 entity 短时间多次写，只发一次
- **失败重试**：最多 6 次，attempts 字段跟踪
- **De-bounce by id**：同一 image_id 短时间多次 write，merge 成一个 push

### 8.2 缓存层

| 缓存 | 位置 | TTL | 容量 | 命中率影响 |
|---|---|---|---|---|
| 文本 embedding | `text_search.py:_query_embed_cache` | 30 min | 512 | 同 query 二次调用 1.5s → 0ms |
| LLM expansion (success) | `query_expansion.py:_cache` | 1 hour | 256 | 重复文案不再调 LLM |
| LLM expansion (failure) | 同上 | 1 hour | 同上 | 防止反复浪费 1.5s timeout |
| Provider embedding shard | `text_search.py:index_cache` | 永久（sidecar 重启重建） | per project | 启动后第一次匹配冷加载 |

- **只读元数据**：永远不上传 OSS（不需要写凭据，commit 142545b）

## 12. 构建与发布

桌面端有完整的 **CI/CD + 自动更新通道**：开发者打 git tag → GitHub Actions 自动跑 Win + Mac installer → 上传阿里云 OSS → 已安装的客户端在下次启动时静默自动更新。

### 12.1 本地开发 vs 生产打包的差异

| 维度 | 开发模式 | 生产 installer |
|---|---|---|
| Sidecar 来源 | `uv run uvicorn ...` 跑源码 | PyInstaller 打成单文件 `sidecar.exe` / `sidecar` |
| 启动方式 | 终端 `npx vite` + `npx electron .` | 用户双击 .dmg / .exe |
| 前端 | Vite dev server (HMR) | esbuild + vite build → `app.asar` |
| 自动更新 | 无 | electron-updater 静默检查 + 后台下载 |
| 数据目录 | `~/lintu-data/` (同) | `~/lintu-data/` (同) — 升级保留用户数据 |

### 12.2 工作流文件

只有一个：[`.github/workflows/build-installers.yml`](../.github/workflows/build-installers.yml)，~285 行。

**触发条件**：
- 手动（Actions tab → Run workflow）
- 推 git tag `v*`（自动 → 出 installer + 上 OSS + GitHub Release）
- 推 v0.2 分支且改动到 `apps/electron/**`、`apps/sidecar/**`、workflow 文件本身

**矩阵策略**：Windows + macOS 各跑一次（matrix.os），步骤完全相同（脚本里 if-else 分平台）。

### 12.3 Build pipeline（每次跑的步骤）

```
checkout
  ↓
setup Node 20 + Python 3.12 + uv
  ↓
sidecar 部分：
  uv sync                                    # 装 Python deps
  uv add --dev pyinstaller                   # 加打包工具
  uv run pyinstaller sidecar.spec --noconfirm --clean
    → apps/sidecar/dist/sidecar/             # 含 sidecar.exe / sidecar 二进制 + _internal/
  ↓
electron 部分：
  npm install --no-package-lock              # 跨平台 lockfile bug 绕开
  esbuild main + preload                     # → dist/main.cjs, dist/preload.cjs
  vite build                                 # → dist/renderer/
  ↓
代码签名（如果配置了 secrets）：
  Win: WIN_CODESIGN_PFX_BASE64 → .pfx
  Mac: MAC_CODESIGN_P12_BASE64 → .p12
  ↓
electron-builder 打包：
  Win: --win --x64 → 灵图-x.y.z-x64.exe (NSIS) + latest.yml
  Mac: --mac --arm64 → 灵图-x.y.z-arm64.dmg + .zip + latest-mac.yml
       (Apple secrets 缺失时降级为 unsigned + 不 notarize)
  ↓
签名验证（仅签名时）：
  Win: PowerShell Get-AuthenticodeSignature
  Mac: codesign --verify + xcrun stapler validate
  ↓
artifact 上传到 GitHub Actions
  ↓
（仅 tag push 时）上传 OSS：
  Python oss2 SDK → put_object_from_file
  → oss://lintu-releases/{windows,mac}/灵图-x.y.z-* + latest.yml
  ↓
（仅 tag push 时）创建 GitHub Release：
  softprops/action-gh-release，从 artifacts 拉所有 installer
```

### 12.4 PyInstaller spec 关键事实

文件：[`apps/sidecar/sidecar.spec`](../apps/sidecar/sidecar.spec)

- **入口**：`sidecar/main.py`（FastAPI app）
- **数据文件**：`alembic.ini` + `alembic/`（迁移在打包后仍能跑 `upgrade head`）
- **Hidden imports**：自动检测 + 手动加（asyncpg / psycopg drivers / jieba 子模块等）
- **输出**：`dist/sidecar/sidecar(.exe)` 单一可执行 + `_internal/` 库目录（不是单文件 onefile，因为 onefile 解压慢首启秒数+5）

### 12.5 electron-builder 关键配置

文件：[`apps/electron/electron-builder.yml`](../apps/electron/electron-builder.yml)

- **appId**：`com.lintu.app`
- **productName**：`灵图`（用户看到的应用名）
- **electronVersion**：39.8.9（pin 固定，避免 workspace 检测失败）
- **asar**：true（前端代码打包，sidecar 走 extraResources 不打）
- **extraResources**：把 PyInstaller 输出的 `dist/sidecar/` 整个塞进 `<app>/resources/sidecar/`，main 进程通过 `process.resourcesPath` 解析路径，跨平台一致

**Windows**：
- target: NSIS installer（用户友好）
- 自定义 publish: 阿里云 OSS `lintu-releases/windows/`

**macOS**：
- target: dmg（首装）+ zip（**electron-updater 必须**，Squirrel.Mac 只认 zip）
- arm64 only（M1 起的所有 Mac，Intel Mac 走 Rosetta）
- hardenedRuntime + entitlements + notarize
- publish: 阿里云 OSS `lintu-releases/mac/`

### 12.6 自动更新通道

**写在哪**：[`apps/electron/src/main/index.ts`](../apps/electron/src/main/index.ts)（`autoUpdater` 配置）

```
应用启动 +10 秒
    ↓
autoUpdater.checkForUpdates()    # 静默
    ↓
访问 https://lintu-releases.oss-cn-hangzhou.aliyuncs.com/{mac,windows}/latest.yml
    ↓
对比 yml 里的版本号 vs package.json 里的版本号
    ↓
有新版？
   ├─ 是 → autoDownload=true 后台下载 .zip(mac) / .exe(win)
   │         ↓
   │       下载完成 → notify renderer ('downloaded')
   │         ↓
   │       autoInstallOnAppQuit=true → 用户下次退出时自动安装
   └─ 否 → 静默，不打扰
```

**前端可见性**：渲染端通过 `notifyUpdater()` IPC 拿到状态（checking / available / progress / downloaded），可以在 UI 顶部显示提示条。

### 12.7 发布一个新版本（运维清单）

```bash
# 1. 在 v0.2 上确认所有要发的代码都已 commit
cd /Users/yang/projects/lintu
git status     # 应当干净
git log --oneline -5

# 2. 改 apps/electron/package.json 的 version (e.g. 0.1.1 → 0.1.2)
vim apps/electron/package.json

# 3. commit + tag
git add apps/electron/package.json

git tag v0.1.2
git push origin v0.2 --tags

# 4. 去 GitHub Actions 看 build-installers job 跑完（约 15-25 min）
# 5. 跑完会自动：
#    - upload artifact 到 GitHub Actions
#    - upload installer 到阿里云 OSS（lintu-releases bucket）
#    - 创建 GitHub Release（含两个 installer 下载链接）
# 6. 已安装的客户端在 +10s 后自动检查到新版，后台下载，下次启动生效
```

### 12.8 Required GitHub Secrets

CI 跑 ALL 功能需要以下 secrets（在 repo Settings → Secrets and variables → Actions 配）：

| Secret | 缺失时的行为 |
|---|---|
| `WIN_CODESIGN_PFX_BASE64` + `WIN_CODESIGN_PFX_PASSWORD` | Win installer 不签名 → SmartScreen 警告但能装 |
| `MAC_CODESIGN_P12_BASE64` + `MAC_CODESIGN_P12_PASSWORD` | Mac 降级 unsigned → Gatekeeper 阻止 |
| `APPLE_ID` + `APPLE_APP_SPECIFIC_PASSWORD` + `APPLE_TEAM_ID` | Mac 不 notarize → Gatekeeper 阻止 |
| `ALIYUN_OSS_ACCESS_KEY_ID` + `ALIYUN_OSS_ACCESS_KEY_SECRET` + `ALIYUN_OSS_BUCKET` + `ALIYUN_OSS_ENDPOINT` | tag push 不上传 OSS → 自动更新拿不到新版（但 GitHub Release 有） |

### 12.9 版本号规范

`apps/electron/package.json` 的 `version` 是唯一来源。建议遵循 SemVer：
- Patch (`0.1.1 → 0.1.2`)：bug 修复 / 文档 / 不影响 API
- Minor (`0.1.x → 0.2.0`)：新功能、向后兼容
- Major (`0.x.x → 1.0.0`)：破坏性变更、protocol 不兼容

git tag 必须 `v` 前缀（`v0.1.2`）— workflow 触发条件是 `tags: ["v*"]`。

### 12.10 已知坑 + 解决方案

| 坑 | 表现 | 解决 |
|---|---|---|
| npm 跨平台 optional deps 丢失 | macOS build 时 vite 报 `MODULE_NOT_FOUND @rollup/rollup-darwin-arm64` | CI 用 `--no-package-lock`（commit 34f6a0f） |
| ossutil 平台不一致 | macOS-arm64 没原生构建 | 改用 oss2 Python SDK 上传（commit 5e4540d） |
| Apple cert secrets 不全 | CI 整个 job fail | 降级为 unsigned + un-notarized macOS 构建（commit 7758473） |
| pwsh `${f}` 解析 | 验证签名时 PowerShell 把 `$f:` 当 drive scope | 用 `${f}:` 显式 brace（commit 5e4540d） |
| Workspace 链接 | electron-builder 找不到 electron 模块 | electron-builder.yml 里 pin `electronVersion` |
